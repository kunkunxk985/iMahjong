## 1. 制定背景与原则

邳州麻将的核心玩法具有高度的地方独特性与严谨性（包含：四家六组两两查胡、散对与暗坎独立计分、庄家胡差翻倍、幺差不翻倍、坎上自杠与送杠、两对关门、单钓飘荤、三类包庄代付等）。

为了保证后续在迭代**东方美学视觉、牌桌动画特效、音效系统、多端适配与大厅社交**等展示层功能时，核心算法不被误改、前后端协议不脱节，现正式确立**规则核心冻结与三层权限管理机制**。

> **核心原则**：
> **UI、动画、音效和牌桌布局可以改；`packages/rules` 规则引擎、`packages/shared` 结算协议和 `packages/server-core` 服务端裁决逻辑不得擅自修改。**

## 3. 核心计算 Invariants（架构不变量法则）

任何参与本项目的工程师必须熟记以下五条不变量法则，任何破坏不变量的提交将被直接拒绝：

1. **服务端绝对权威**：
   - 所有的摸打、吃碰杠坎、自摸点炮裁决、两两查胡、六笔收付账单与底分对账，**100% 由服务端与 Worker 计算**。
   - 桌面客户端是纯展示层，只能通过 WebSocket 接收 `ClientView` 与 `Settlement` 进行状态同步和视觉渲染，**严禁在前端本地计算胡数或代扣筹码**。

2. **六组两两独立清算**：
   - 邳州麻将不是简单的“赢家拿三家”。每局结束，四家（0-1, 0-2, 0-3, 1-2, 1-3, 2-3）分别查胡对账。
   - **没胡的玩家手中的散对和暗坎也必须计分**（普通对1胡/幺头对2胡/普通坎2胡/幺头坎4胡1幺），参与两两差额清算。

3. **庄家与飘荤翻倍逻辑**：
   - 牌面基础胡数是客观事实，不随身份改变（庄家 6 胡牌面仍是 6 胡，不可伪改成 12 胡）。
   - 翻倍仅作用于两两胡差：原始胡差计算后，若涉及庄家乘 2；若该笔涉及飘荤乘 2；若既飘荤又涉及庄家，则胡差整体乘 4。
   - **幺差永远不参与翻倍**（无论是否庄家或飘荤，幺差始终为 `(A幺 - B幺) × 10`）。

4. **包庄代付机制**：
   - 触发包庄时，并非取消其他家的查胡，而是**由包庄者一人全额代付另外两家本应付给胡家的正向金额**；其他玩家之间的差胡正常互结。若有 30 分荤底，亦全额由包庄者承担。

5. **协议契约严格向后兼容**：
   - `packages/shared/src/types.ts` 和 `events.ts` 是客户端与服务端的通讯协议，绝不可擅自删除现有字段或重命名字段，新增字段必须设为可选（`optional`）。

## 4. 八项正式“锁死”的本房房规决议

针对考据文档与地方牌桌常见歧义，本项目已将以下 8 条细则正式确立为**本房官方标准房规**，代码逻辑已冻结并受测试保护，后续无需重复讨论：

| 序号 | 规则争议项 | 本房锁死决议 | 决议 rationale 与落地保障 |
|:---:|---|---|---|
| **1** | **流局换庄规则** | **仅庄家实际胡牌才连庄；闲家胡牌或摸完流局均轮换至下家坐庄** | 符合苏北友友标准；流局无胜者不连庄，保证四家轮庄公平性。 |
| **2** | **未声明的四张相同牌** | **按一坎加一张散牌计算，不追认自杠，亦不算两个对子** | 查胡必须以行动为准，未报杠就不能享受杠的胡数加成。 |
| **3** | **“坎上”声明机制** | **坎上必须在对局中主动声明并锁定** | 只有主动声明坎上才能防吃碰、算入两对关门/单钓组数，以及后续自摸摸到第四张自杠；未声明的暗刻仅在终局查胡时按基础暗坎计 2 胡。 |
| **4** | **胡与幺的折算比例** | **永久固定为 `1 胡 = 1 分`，`1 幺 = 10 分`** | 统一两两清算换算基准，消除不同桌面分值歧义。 |
| **5** | **一炮多响裁决** | **截胡制：只取行牌顺序距离点炮者最近的一家** | 不设一炮多响，不设点炮者全包多人。最近下家优先胡牌。 |
| **6** | **补杠与抢杠胡** | **不设补杠，不设抢杠胡** | 碰后即便摸到第四张也不能再杠；坎上自杠只允许本人自摸第四张；别人打第四张算送杠（直杠）。 |
| **7** | **四家首张同牌** | **直接流局，并按正常流局换庄** | 四家第一巡出牌完全相同时（如四张一万）触发四归一流局，不计分直接进入下一局。 |
| **8** | **番型支持范围** | **仅支持标准“四组牌加一对”平胡、两对关门与飘荤；不支持七对、十三幺** | 保持纯正邳州本土麻将风味，杜绝外来非正统杂番。 |

## 5. 质量门禁与 CI 验证命令

项目已在 GitHub CI 和本地配置了严格的多层自动化卡点。提交任何 PR 或合并代码前，必须在本地完整运行通过：

```bash
npm run verify
```

该命令包含以下必须 100% 全绿的 5 项检查链：
1. `npm run check:architecture`：架构边界检查（防止层级倒错、浏览器端误用 Node 库、运行素材完整性）；
2. `npm run typecheck`：全工作区（desktop, server, server-core, rules, shared, worker）TypeScript 类型 0 错误；
3. `npm test`：全量单元测试（包含 97 项规则引擎测试、24 项 server-core 测试、12 项 worker 测试）；
4. `npm run smoke`：四人真实联机、断线重连、再来一局、单机陪练全流程集成冒烟测试；
5. `npm run build`：桌面客户端与核心包 Vite 生产打包验证。
