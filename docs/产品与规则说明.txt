# 邳州麻将联机桌面 Demo 开发文档 v0.1

## 1. 项目目标

开发一个可安装在 Windows 和 macOS 上的邳州麻将桌面 Demo。

本版本只满足四个朋友通过房间号联机打麻将的基本需求：

- 4 名真人进入同一个房间。
- 房主开始游戏。
- 完成一局基础邳州麻将。
- 支持吃、碰、杠、胡。
- 支持基础胡数和幺数结算。
- 支持再来一局。
- 支持掉线重连。

本版本不开发大型棋牌游戏平台，不开发商城、账号、排行榜、AI、语音、观战、赛事、充值、提现或真实货币玩法。

## 4. 邳州麻将基础规则

本 Demo 采用邳州麻将基础玩法，也称查胡麻将。以下内容分为两层：

- “公开规则”：以友友互动公开的“友友邳州麻将”说明为主要依据，并用其他公开条目交叉核对。
- “本房房规”：公开材料未明确、线上对局必须固定，或不同牌桌可能存在差异的细节。

地方玩法可能存在差异。服务端是唯一裁判，规则弹窗、结算页、测试和本文档必须同步；详见 `docs/邳州麻将规则考据.md`。

公开规则参考：

https://www.yooyogame.com/games.shtml

### 4.1 牌库

共 120 张牌：

```text
一万至九万：36 张
一筒至九筒：36 张
一条至九条：36 张
中、发、白：12 张
```

不使用：

- 东、南、西、北风牌。
- 花牌。
- 癞子牌。
- 财神牌。
- 红中替代牌。

### 4.2 座位和庄家

- 固定 4 名玩家。
- 本房房规：房主第一局默认担任庄家。
- 庄家胡牌，下一局继续坐庄。
- 只要不是庄家胡牌，包括闲家胡牌和流局，下一局都由庄家的下一家坐庄。
- 流局换庄是项目对公开原句“如果不是庄家胡牌，则轮庄”的实现解释；公开页没有单列流局，仍建议由实际邳州牌友确认。

### 4.3 发牌

- 庄家起手 14 张。
- 其他玩家起手 13 张。
- 庄家先出牌。
- 之后轮流摸牌和出牌。
- 本房房规：牌墙摸完且无人胡牌，判定流局。
- 本房房规：流局不结算分数，并按上节规则换庄。

### 4.4 操作优先级

```text
胡 > 杠 > 碰 > 吃
```

本房房规：一局只有一名胡牌者。一炮多人可胡时，只取从出牌者起按行牌顺序最近的一家。

### 4.5 吃牌

- 只能吃上家的牌。
- 只能组成顺子。
- 不能吃对家和下家的牌。
- 中、发、白不能组成顺子。
- 吃牌优先级低于碰牌和杠牌。
- 吃牌不增加胡数。
- 吃牌后必须出牌。

### 4.6 碰牌

- 任意玩家打出的牌都可以碰。
- 手中需要有两张相同牌。
- 碰牌后形成明刻。
- 碰牌后必须出牌。
- 落地碰按碰计胡，不算主动坎上。

### 4.7 杠牌

Demo 支持：

- 暗杠。
- 送杠：手里已有三张相同牌（无论是否先坎上），接到别人打出的第四张。
- 自杠：已坎上的三张由自己摸到第四张。
- 本房房规：碰牌后不能再杠，不存在补杠。

杠牌流程：

```text
亮出杠牌
→ 从牌尾补牌
→ 检查是否胡牌
→ 没有胡牌则继续出牌
```

### 4.8 胡牌

首发只支持：

- 平胡。
- 起手杠胡。

平胡牌型：

```text
一对将牌 + 四组顺子、刻子或杠子
```

起手杠胡：

- 发牌后发现手中有杠。
- 玩家可以选择直接胡牌。
- 玩家也可以选择继续打牌。
- 起手杠胡直接进入结算。

## 5. Demo 计分

### 5.1 基础单位

任何玩家胡牌固定增加：

```text
10 胡
```

幺牌包括：

```text
一万、九万
一筒、九筒
一条、九条
中、发、白
```

### 5.2 计分表

| 组合 | 普通牌 | 幺九牌 |
|---|---:|---:|
| 对（含胡牌将牌） | 1 胡 | 2 胡 |
| 碰（含点炮补成三张） | 1 胡 | 2 胡 |
| 坎 | 2 胡 | 4 胡 1 幺 |
| 送杠（明杠） | 4 胡 | 8 胡 2 幺 |
| 自杠（含暗杠） | 6 胡 | 12 胡 3 幺 |

### 5.3 结算

本房积分配置：

```text
1 胡 = 1 分
1 幺 = 10 分
```

计算方式：

```text
牌面分（倍率前） = 胡总数 + 幺总数 × 10

A 的飘荤后胡 = A 的牌面胡 × (A 飘荤 ? 2 : 1)
B 的飘荤后胡 = B 的牌面胡 × (B 飘荤 ? 2 : 1)
两两原始胡差 = A 的飘荤后胡 - B 的飘荤后胡
两两胡差 = 两两原始胡差 ×（A 或 B 是庄家 ? 2 : 1）
两两幺差 = A 的幺数 - B 的幺数
本笔结算 = 两两胡差 + 两两幺差 × 10

放炮与自摸不附加结算倍率，只影响胡进来的第三张按碰还是按坎计分
飘荤只先折算飘荤者的胡数；庄家不改变任何人的牌面胡数，只把涉及庄家的整笔胡差翻倍；幺差与荤底不翻倍
```

示例：飘荤闲家 17 胡对庄家 6 胡，先算 `17×2=34`，再算 `34−6=28`；因为涉及庄家，最终胡差为 `28×2=56`，而不是把庄家的 6 胡先乘 2。

坎、送杠和自杠必须按牌局中的真实来源登记：

```text
手里三张相同可以主动确认“坎上”，锁定且不能拆打；坎上用于飘荤、关门、包庄组数以及后续自杠
查胡时未主动坎上的三张仍按暗坎计基础胡，但不追溯成已经锁定的进阶组数
落地碰按碰计；点炮补成第三张也按碰计，不升级为坎：普通牌 1 胡，幺头牌 2 胡
手里三张相同后接别人打出的第四张：送杠（不要求先坎上）
已有坎后自己摸到第四张：自杠
已有碰后自己摸到第四张：不能杠，第四张留在手牌中正常使用或打出
手里四张一次性开出暗杠，或坎后自摸第四张形成自杠：都按自杠档计分
本房房规：四张相同但未声明杠，查胡时只按一坎加一张散牌，不追认自杠或两个对子
自摸成刻：按坎计胡，普通牌 2 胡，幺头牌 4 胡并加 1 幺
没胡的人同样查手牌：对子、暗坎照常计胡；已落地的碰、坎和杠按真实来源计分
胡牌结构里的将牌按对计胡：普通牌 1 胡，幺头牌 2 胡，均不加幺
双碰胡时，最后补成的三张点炮按碰、自摸按坎；留下的将牌仍按对计胡
单钓仍可胡，最后补成的将牌照常按对计胡
结算时不得把顺子拆成坎，也不得把未杠的牌计成杠
赢家必须采用合法的“四组一对”拆分，每张牌只用一次；多种合法拆分按本房积分配置取分值较高者
```

两对关门：

```text
已有四组牌、手里只剩一张单钓最后对子时，自动进入关门状态
单钓关门可以换听口并继续保持锁牌状态，但一旦换过张，本局永久失去“不换张听顺包庄”资格
已有三组碰、坎或杠，自己出牌后手里恰好剩两对，可在出牌时声明关门
两对关门后可以拆对子换听，但关门立即失效
关门本身不加胡、不加幺；两对关门玩家不受“包香不包臭”规则限制
宣布关门这一手打出的牌也算臭牌
按全桌历史判断：此前任何玩家打过的是臭牌，即使后来被吃、碰、杠取走也不能重新变香；从未出现过的是香牌
当前刚打出的点炮牌先判胡，不能在包香判断前提前写入臭牌历史
三组碰、坎或杠加两对但未选择两对关门时，被全桌此前未出现过的香牌点炮，由出牌者包另外两家的结算，并按飘荤结算；打出臭牌不包庄；选择两对关门后不触发包香
关门状态公开显示；有效期间不能重复声明，失效后再次满足条件可重新关门
```

补充边界：

```text
本房房规：没有补杠，也没有抢杠胡
本房房规：杠上开花按普通自摸，不额外加胡或翻倍
三个普通碰加两对胡牌也算飘荤；碰计入组数，但仍按碰的胡值计分
本房房规：一炮多人可胡时，只允许从出牌者起按行牌顺序最近的一家胡
本房房规：开局四家第一张弃牌相同则直接流局，并依正常规则换庄
```

三类包庄：

```text
四组全为碰、坎或杠，手里剩一张且始终未换张；点炮牌与该单张能相连成顺：按飘荤包庄
四组中含吃，手里剩一张且始终未换张；点炮牌与该单张能相连成顺：按普通胡包庄
三组碰、坎或杠加两对但未选择两对关门，被此前从未出现过的香牌点炮：按飘荤包庄；打出臭牌不包庄；选择两对关门后不触发包香
包庄者代付另外两家原本应向胡家支付的全部份额；若有荤底，三家的荤底也全部由包庄者承担，其余闲家免责为0分
```

庄家参与的两两结算：

```text
双方先按牌面胡数查差；若这一笔涉及庄家，整笔胡差 × 2
庄家本人的牌面胡数不先单独乘 2
飘荤只在查胡差前把飘荤者的胡数 × 2
幺差不翻倍
```

放炮与自摸：

```text
放炮和自摸不附加结算倍率
点炮把对子补成三张时按碰计分
自摸把对子补成三张时按坎计分
```

查胡结算：

```text
四家按胡数和幺数两两比较并结算差额
飘荤者的胡数先 ×2；涉及庄家的胡差再整体 ×2
牌面胡数不改；幺数差不翻倍
四家的本局增减合计必须为 0
```

## 6. 房间流程

### 6.1 创建房间

```text
玩家输入昵称
→ 点击创建房间
→ 服务端生成 6 位数字房间号
→ 玩家成为房主并进入东位（本房首庄约定）
```

### 6.2 加入房间

玩家输入昵称和房间号。

服务端检查：

- 房间是否存在。
- 房间是否已满。
- 昵称是否重复。
- 房间是否已经开始。

### 6.3 开始游戏

只有满足以下条件才能开始：

```text
4 名玩家全部进入
4 名玩家全部准备
点击开始的是房主
```

### 6.4 再来一局

- 一局结束后展示四人分数。
- 四人准备下一局。
- 房主点击开始下一局。
- 按庄家规则重新确定庄家。
- 重新洗牌和发牌。

## 7. WebSocket 设计

服务端是唯一规则裁判。

### 7.1 客户端事件

```text
room:create
room:join
room:leave
room:ready
room:start
game:action
game:nextRound
player:reconnect
ping
```

### 7.2 服务端事件

```text
game:state
game:settlement
game:roundStarted
player:disconnected
player:reconnected
error
pong
```

### 7.3 游戏操作

```json
{
  "type": "game:action",
  "actionId": "action-001",
  "sequence": 128,
  "action": {
    "kind": "discard",
    "tileId": "wan-3-2"
  }
}
```

服务端必须防止：

- 重复提交。
- 过期操作。
- 非当前玩家操作。
- 非法牌面。
- 非法吃牌来源。
- 非法碰牌和杠牌。
- 客户端伪造分数。

每次状态广播都要包含 sequence。

其他玩家只能看到：

- 手牌数量。
- 弃牌。
- 明牌组合。
- 玩家状态。

不能看到其他玩家的具体手牌。

## 8. 断线重连

- 客户端每 10 秒发送一次心跳。
- 服务端保留掉线玩家座位 30 分钟。
- 其他玩家看到“已断线”状态。
- 玩家重连后恢复原座位。
- 玩家重连后恢复手牌、弃牌、明牌和当前回合。
- 不做 AI 代打。

- Windows可以启动。

- Windows和macOS可以同时完成一局。
- 窗口缩放后牌桌不重叠。
- 最小窗口尺寸下操作仍然可用。

## 12. 开发阶段

### 阶段一：房间和联机

完成创建房间、加入房间、准备、开始、退出和断线重连。

### 阶段二：规则引擎

完成牌库、发牌、摸牌、出牌、吃、碰、杠、胡和基础结算。

### 阶段三：桌面界面

完成Electron窗口、牌桌布局、手牌、弃牌、操作按钮和结算页面。

### 阶段四：测试和打包

完成规则测试、联机测试、Windows打包和macOS打包。

## 13. 开发命令

```bash
npm install
npm run dev:server
npm run dev:desktop
npm run build
npm run package:win
npm run package:mac
```

package.json至少提供：

```json
{
  "scripts": {
    "dev:server": "...",
    "dev:desktop": "...",
    "build": "...",
    "package:win": "electron-builder --win",
    "package:mac": "electron-builder --mac --arm64 --dir"
  }
}
```

当前 macOS 私用交付只生成 Apple Silicon `.app` 应用目录并复制到桌面，不生成 DMG 安装镜像。

## 14. 最终验收标准

1. Windows和macOS都能启动。
2. 4名玩家可以通过房间号进入同一房间。
3. 四人准备后可以开始游戏。
4. 玩家可以正常摸牌、出牌、吃、碰、杠和胡。
5. 吃牌只能吃上家。
6. 服务器统一判断合法操作。
7. 胡数和幺数结算正确。
8. 一局结束后可以查看四人得分。
9. 可以再来一局。
10. 掉线后可以重连。
11. 项目不会修改 C:\Users\14416\Desktop\iStudy。
12. 项目可以通过 README 中的命令启动。
13. 项目可以生成Windows安装包。
14. 项目可以生成macOS安装包。
