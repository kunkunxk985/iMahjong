# 邳州麻将联机桌面 Demo 开发文档 v0.1

## 1. 项目目标

开发一个可安装在 Windows 和 macOS 上的邳州麻将桌面 Demo。

本版本只满足四个朋友通过房间号联机打麻将的基本需求：

- 4 名真人进入同一个房间。
- 房主开始游戏。
- 完成一局基础邳州麻将。
- 支持吃、碰、杠、胡。
- 支持基础胡数和幺数结算。
- 支持再来一局。
- 支持掉线重连。

本版本不开发大型棋牌游戏平台，不开发商城、账号、排行榜、AI、语音、观战、赛事、充值、提现或真实货币玩法。

## 4. 邳州麻将基础规则

本 Demo 采用邳州麻将基础玩法，也称查胡麻将。地方玩法可能存在差异，所有差异都必须配置化。

公开规则参考：

https://www.yooyogame.com/games.shtml

### 4.1 牌库

共 120 张牌：

```text
一万至九万：36 张
一筒至九筒：36 张
一条至九条：36 张
中、发、白：12 张
```

不使用：

- 东、南、西、北风牌。
- 花牌。
- 癞子牌。
- 财神牌。
- 红中替代牌。

### 4.2 座位和庄家

- 固定 4 名玩家。
- 房主第一局默认担任庄家。
- 庄家胡牌，下一局继续坐庄。
- 闲家胡牌，下一局顺时针轮庄。
- 流局时庄家继续坐庄。

### 4.3 发牌

- 庄家起手 14 张。
- 其他玩家起手 13 张。
- 庄家先出牌。
- 之后轮流摸牌和出牌。
- 牌墙摸完且无人胡牌，判定流局。
- 流局不结算分数。

### 4.4 操作优先级

```text
胡 > 杠 > 碰 > 吃
```

Demo 默认一局只有一名胡牌者，不允许一炮多胡。

### 4.5 吃牌

- 只能吃上家的牌。
- 只能组成顺子。
- 不能吃对家和下家的牌。
- 中、发、白不能组成顺子。
- 吃牌优先级低于碰牌和杠牌。
- 吃牌不增加胡数。
- 吃牌后必须出牌。

### 4.6 碰牌

- 任意玩家打出的牌都可以碰。
- 手中需要有两张相同牌。
- 碰牌后形成明刻。
- 碰牌后必须出牌。
- 明碰不计作坎。

### 4.7 杠牌

Demo 支持：

- 暗杠。
- 明杠。
- 补杠。

杠牌流程：

```text
亮出杠牌
→ 从牌尾补牌
→ 检查是否胡牌
→ 没有胡牌则继续出牌
```

### 4.8 胡牌

首发只支持：

- 平胡。
- 起手杠胡。

平胡牌型：

```text
一对将牌 + 四组顺子、刻子或杠子
```

起手杠胡：

- 发牌后发现手中有杠。
- 玩家可以选择直接胡牌。
- 玩家也可以选择继续打牌。
- 起手杠胡直接进入结算。

## 5. Demo 计分

### 5.1 基础单位

任何玩家胡牌固定增加：

```text
10 胡
```

幺牌包括：

```text
一万、九万
一筒、九筒
一条、九条
中、发、白
```

### 5.2 计分表

| 组合 | 普通牌 | 幺九牌 |
|---|---:|---:|
| 对子 | 1 胡 | 2 胡 |
| 坎 | 2 胡 | 4 胡 1 幺 |
| 明杠 | 4 胡 | 8 胡 2 幺 |
| 暗杠或自杠 | 6 胡 | 12 胡 3 幺 |

### 5.3 结算

Demo 中：

```text
1 胡 = 1 分
1 幺 = 10 分
```

计算方式：

```text
最终分数 = 胡总数 + 幺总数 × 10
```

坎、送杠和自杠必须按牌局中的真实来源登记：

```text
手里真实持有三张相同牌时提示“坎上”；只有玩家确认坎上后才登记为坎并计胡
坎上的三张牌立即锁定并移入固定牌组，之后不能拆开出牌
已有坎后接别人打出的第四张：送杠
已有坎后自己摸到第四张：自杠
点炮胡进来的第三张：只完成胡牌，原来的两张仍按对子计胡，不升级为坎
```

未主动坎上的三张相同牌不计坎胡。结算时不得为了取得更高胡数而重新拆牌、虚构坎或杠。

庄家胡牌：

```text
胡数 × 2
幺数不翻倍
```

放炮和自摸暂时使用相同分值。

默认结算：

```text
胡牌者获得最终分数
其他三名玩家各扣除相同分数
```

## 6. 房间流程

### 6.1 创建房间

```text
玩家输入昵称
→ 点击创建房间
→ 服务端生成 6 位房间号
→ 玩家成为房主并进入东位
```

### 6.2 加入房间

玩家输入昵称和房间号。

服务端检查：

- 房间是否存在。
- 房间是否已满。
- 昵称是否重复。
- 房间是否已经开始。

### 6.3 开始游戏

只有满足以下条件才能开始：

```text
4 名玩家全部进入
4 名玩家全部准备
点击开始的是房主
```

### 6.4 再来一局

- 一局结束后展示四人分数。
- 四人准备下一局。
- 房主点击开始下一局。
- 按庄家规则重新确定庄家。
- 重新洗牌和发牌。

## 7. WebSocket 设计

服务端是唯一规则裁判。

### 7.1 客户端事件

```text
room:create
room:join
room:leave
room:ready
room:start
game:action
game:nextRound
player:reconnect
ping
```

### 7.2 服务端事件

```text
room:state
game:state
game:actionRequired
game:settlement
game:roundStarted
player:disconnected
player:reconnected
error
pong
```

### 7.3 游戏操作

```json
{
  "type": "game:action",
  "actionId": "action-001",
  "roomId": "AB12CD",
  "playerId": "player-2",
  "action": {
    "type": "DISCARD",
    "tileId": "wan_3_2"
  },
  "clientSequence": 128
}
```

服务端必须防止：

- 重复提交。
- 过期操作。
- 非当前玩家操作。
- 非法牌面。
- 非法吃牌来源。
- 非法碰牌和杠牌。
- 客户端伪造分数。

每次状态广播都要包含 sequence。

其他玩家只能看到：

- 手牌数量。
- 弃牌。
- 明牌组合。
- 玩家状态。

不能看到其他玩家的具体手牌。

## 8. 断线重连

- 客户端每 10 秒发送一次心跳。
- 服务端保留掉线玩家座位 30 分钟。
- 其他玩家看到“已断线”状态。
- 玩家重连后恢复原座位。
- 玩家重连后恢复手牌、弃牌、明牌和当前回合。
- 不做 AI 代打。

## 9. Electron 桌面端要求

安全配置：

```js
{
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true
}
```

其他要求：

- 默认窗口 1280×800。
- 最小窗口 1024×700。
- 支持Windows和macOS窗口缩放。
- 不写死 Windows 路径。
- 路径统一使用 path.join。
- 用户数据统一使用 app.getPath('userData')。
- 不提交 node_modules。
- 必须提交 package-lock.json 或其他锁文件。
- WebSocket服务器地址通过 .env 或设置项配置。
- localhost 只用于本机测试。

## 10. 界面设计

页面只需要：

```text
连接服务器页
创建/加入房间页
等待房间页
对局页
结算页
设置弹窗
规则说明弹窗
```

对局界面：

```text
顶部：上家
左侧：左家
右侧：右家
底部：自己
中心：弃牌区和牌墙
```

显示：

- 玩家昵称。
- 玩家座位。
- 玩家连接状态。
- 玩家积分。
- 庄家标记。
- 当前局数。
- 剩余牌数。
- 操作倒计时。
- 弃牌区。
- 明牌区。
- 自己的手牌。

按钮：

```text
吃
碰
杠
胡
过
```

没有合法操作时，按钮隐藏或禁用。

视觉方向：

- 深翡翠绿牌桌。
- 暖白色牌面。
- 红色强调按钮。
- 少量铜金色装饰。
- 清晰的立体麻将牌。
- 选中牌轻微上浮。
- 出牌有落桌动画。
- 胡牌有短暂高亮。
- 不制作营销型首页。
- 不使用未经授权的品牌、人物或图片。

## 11. 测试要求

### 11.1 规则测试

- 牌库数量为 120 张。
- 不存在风牌和花牌。
- 只能吃上家。
- 不能吃对家和下家。
- 中发白不能组成顺子。
- 胡优先级高于杠。
- 杠优先级高于碰。
- 碰优先级高于吃。
- 起手杠可以直接胡。
- 吃牌不增加胡数。
- 对子、坎、明杠、暗杠计分正确。
- 幺九牌计分正确。
- 庄家胡数翻倍。
- 幺数不翻倍。
- 流局不结算。

### 11.2 联机测试

- 4 人可以加入同一房间。
- 第 5 人无法加入满员房间。
- 房间号错误时显示提示。
- 昵称不能重复。
- 只有房主可以开始游戏。
- 未准备玩家不能开始。
- 非当前玩家不能出牌。
- 重复操作不会重复执行。
- 断线后可以重连。
- 重连后手牌和座位正确。
- 服务端重启后客户端显示房间失效。

### 11.3 跨平台测试

- Windows可以启动。
- macOS可以启动。
- Windows可以创建房间。
- macOS可以加入Windows创建的房间。
- Windows和macOS可以同时完成一局。
- 窗口缩放后牌桌不重叠。
- 最小窗口尺寸下操作仍然可用。
