# 邳州麻将规则考据与项目口径

更新日期：2026-09-01

这份文档记录“为什么这样实现”，避免引擎、规则弹窗、结算页和测试再次各说各话。邳州不同牌桌可能有房规差异；本项目以公开资料能确认的共同规则为底座，把其余选择显式标成“实现解释”或“本房房规”。

## 1. 来源分级

### A 级：主要基线

- [苏州友友互动《友友邳州麻将》规则](https://www.yooyogame.com/games.shtml)

该页面由游戏运营方发布，完整列出牌库、吃碰优先级、轮庄、起手杠、查胡计分、飘荤与三类包庄，是当前公开可访问资料中最适合作为实现基线的一份。

局限：页面没有修订日期，平台信息仍是较早期 Android 版本，因此它可以高可信地代表“友友邳州麻将”这一实现，但不能被描述成所有邳州牌桌唯一、永不变化的地方标准。

### B 级：交叉核对

- [搜狗百科《邳州麻将》](https://baike.sogou.com/v69033061.htm)

基础计分与友友规则高度一致，但可能是转录，并夹带其他线上版本的简化说明。用于发现玩法变体，不用于推翻 A 级来源的明确条款。

### C 级：只核对基础项

- [游戏堡《邳州麻将手机版》](https://www.yxbao.com/game/5002683.html)

可交叉核对 120 张、只能吃上家、吃低于碰杠等基础项；页面包含网友上传和通用营销文案，不用于裁决精细计分。

| 规则项 | 项目口径 | 依据强度 |

| 吃牌 | 只能吃上家；吃的优先级低于碰、杠 | 高 |
| 胡牌结构 | 一对将牌加四组顺子、坎或杠 | 高 |
| 查胡 | 一局结束后四家分别计算并两两结算 | 高 |
| 胡牌基础 | 胡牌者固定加 10 胡 | 高 |
| 普通对子 | 1 胡，不加幺 | 高 |
| 幺头对子 | 2 胡，不加幺 | 高 |
| 普通坎 | 2 胡 | 高 |
| 幺头坎 | 4 胡、1 幺 | 高 |
| 普通送杠 / 自杠 | 4 胡 / 6 胡 | 高 |
| 幺头送杠 / 自杠 | 8 胡 2 幺 / 12 胡 3 幺 | 高 |
| 放炮与自摸 | 不额外形成全局倍率；最后一张补成刻子时，点炮按碰、自摸按坎 | 高 / 实现解释 |
| 庄家倍率 | 本房确认：不改庄家牌面胡；涉及庄家的两两胡差整体乘 2，幺数不翻 | 本房规则 |
| 飘荤倍率 | 牌面胡数不变；两两先查原始胡差，再将本笔胡差乘 2；同一笔再涉及庄家时胡差整体乘 2 | 本房规则 |
| 荤底 | 飘荤胡家另向其余三家各收 30 分 | 高 |
| 起手杠 | 起手四张相同可以立即杠胡，也可以继续打 | 高 |
| 包庄 | 四组单钓听顺、含吃单钓听顺、三组两对包香三类 | 中高 |

“对子”和“坎”是公开计分表中的独立项目，且查胡是四家分别结算。因此项目采用：没胡的人手里的对子和暗坎也参与查胡。公开页没有给出逐张拆分算法，但把它们全部忽略与公开计分表不相容。

## 3. 本房确认的结算模型

前一版实现曾把飘荤先作用于赢家牌面，导致“飘荤闲家 17 胡对普通闲家 6 胡”被算成 `34−6=28`。本房最新确认的口径是：牌面胡数固定，先算 `17−6=11`，再将本笔胡差翻倍为 22；如果这组再涉及庄家，则 22 再翻倍为 44。

```text
两两原始胡差 = A 的牌面胡 - B 的牌面胡
本笔飘荤胡差 = 两两原始胡差 ×（本笔涉及飘荤 ? 2 : 1）
两两胡差 = 本笔飘荤胡差 ×（A 或 B 是庄家 ? 2 : 1）
两两幺差 = A 的幺数 - B 的幺数
本房积分 = 两两胡差 + 两两幺差 × 10
```

例：飘荤闲家 17 胡对庄家 6 胡，先算原始胡差 `17−6=11`，本笔飘荤后为 `11×2=22`，最后因涉及庄家得到 `22×2=44`。庄家的 6 胡不先单独乘 2，幺差也不翻倍。

这个模型保留牌面胡数，只在结算关系上处理庄家倍率：庄家 6 胡对闲家 11 胡，原始胡差为 `6−11=-5`，涉及庄家后为 `-5×2=-10`；UI 必须把“胡差×2”展示清楚，不能伪装成庄家牌面胡数变成 12 胡。

## 4. 三类包庄的实现口径

1. 四组碰、坎或杠后单钓，听口始终未换；点炮牌与手中单张能组成顺子：按飘荤包庄。
2. 四组中含吃后单钓，听口始终未换；点炮牌与手中单张能组成顺子：按普通胡包庄。
3. 三组碰、坎或杠加两对但未选择两对关门时，被此前全桌从未出现过的“香牌”点炮：由打出生张的点炮者按飘荤包庄；若点炮牌在此前牌河已经出现过，属于“臭牌”，正常点炮不包庄；两对关门玩家不受这条包香规则限制。

先完整保留四家六组两两查胡流水；包庄者代付另外两家原本应向胡家支付的正向份额，胡家与高胡玩家的反向差额、以及另外玩家之间的差胡仍照算；若有荤底，三家的荤底也全部由包庄者承担。代码必须记录：

- 单钓后是否换过听口；
- 关门前全桌已经出现过哪些弃牌；
- 两对关门是否仍有效。

A 级来源第二类包庄有疑似错字，因此项目按上下文理解为“已完成四组且其中含吃”的普通单钓听顺。该条属于中高置信实现，不应描述成毫无歧义的逐字原文。

## 5. 实现解释与本房房规（已正式确认并锁死）

以下 8 项属于地方牌桌存在变体但本项目已**正式确认并代码冻结**的官方基准，后续任何开发不得擅自变动：

| 序号 | 项目 | 本房正式决议 | 分类 | 依据与处理逻辑 |
|:---:|---|---|---|---|
| **1** | **流局轮庄** | **只有庄家实际胡牌才连庄；闲家胡或摸完流局均轮换至下一家坐庄** | 本房正式房规 | 流局无赢家，不下庄对闲家不公平；符合友友公开基准。 |
| **2** | **未声明四张** | **按一坎加一张散牌计算，不追认自杠或两个对子** | 本房正式房规 | 查胡以桌面声明为准，未报杠则按暗坎计 2 胡，散牌 0 胡。 |
| **3** | **坎上声明** | **必须在对局中主动声明并锁定** | 核心机制 | 用于锁牌、飘荤/关门/包庄组数计算与后续自杠；未声明的真实暗刻仅在终局参与基础查胡（2胡），不可中途追认为已锁定坎。 |
| **4** | **胡幺折分** | **永久固定为 `1 胡 = 1 分`、`1 幺 = 10 分`** | 本房正式房规 | 消除不同牌友换算歧义；胡差与幺差分别独立折算。 |
| **5** | **一炮多人** | **截胡制：只取行牌顺序距出牌者最近的一家** | 本房正式房规 | 保护放炮者不过度失分，按出牌逆时针顺序最近下家优先胡牌。 |
| **6** | **补杠 / 抢杠胡** | **均不设；碰后第四张留在手里不可再杠** | 本房正式房规 | 坎上自杠只允许自摸第四张；别人打出第四张为送杠；已落地碰不可再补杠。 |
| **7** | **四家首张同牌** | **直接流局，并按正常流局换庄** | 本房正式房规 | 开局四家首打同一牌面（如四张一万）触发四归一流局，不计分直接进入下一局。 |
| **8** | **番型支持范围** | **仅支持“四组牌加一对”经典平胡、两对关门与飘荤；不支持七对等外来番型** | 范围界限 | 保证纯正江淮老家传统玩法，不加入七对、十三幺等杂番。 |

除上述 8 条外，补充约定：
- **首局庄家**：建房房主坐东庄；
- **杠上开花**：按普通自摸计分，不额外加番；
- **多种合法拆分**：按当前房间积分配置取最终结算分值较高的拆分方案，避免同一手牌产生不同得分。

## 6. 规则核心冻结与团队开发要求

本文件确立的全部规则与算分算法已在 `packages/rules` 中冻结，并通过了 97 项规则单元测试与多端联机 Smoke 测试。

相关开发约束：
1. **开发权限控制**：遵循 `docs/规则核心冻结与团队开发规范.md` 与 `.github/CODEOWNERS`，禁止前端展示层或服务端调度擅自修改算分逻辑；
2. **自动化校验**：任何与牌桌相关的改动必须通过 `npm run verify`，确保类型检查、单元测试、架构边界与联机冒烟 100% 全绿。
