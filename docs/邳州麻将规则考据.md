# 邳州麻将规则考据与项目口径

更新日期：2026-09-01

这份文档记录“为什么这样实现”，避免引擎、规则弹窗、结算页和测试再次各说各话。邳州不同牌桌可能有房规差异；本项目以公开资料能确认的共同规则为底座，把其余选择显式标成“实现解释”或“本房房规”。

## 1. 来源分级

### A 级：主要基线

- [苏州友友互动《友友邳州麻将》规则](https://www.yooyogame.com/games.shtml)

该页面由游戏运营方发布，完整列出牌库、吃碰优先级、轮庄、起手杠、查胡计分、飘荤与三类包庄，是当前公开可访问资料中最适合作为实现基线的一份。

局限：页面没有修订日期，平台信息仍是较早期 Android 版本，因此它可以高可信地代表“友友邳州麻将”这一实现，但不能被描述成所有邳州牌桌唯一、永不变化的地方标准。

### B 级：交叉核对

- [搜狗百科《邳州麻将》](https://baike.sogou.com/v69033061.htm)

基础计分与友友规则高度一致，但可能是转录，并夹带其他线上版本的简化说明。用于发现玩法变体，不用于推翻 A 级来源的明确条款。

### C 级：只核对基础项

- [游戏堡《邳州麻将手机版》](https://www.yxbao.com/game/5002683.html)

可交叉核对 120 张、只能吃上家、吃低于碰杠等基础项；页面包含网友上传和通用营销文案，不用于裁决精细计分。

## 2. 已采用的公开规则

| 规则项 | 项目口径 | 依据强度 |
|---|---|---:|
| 牌库 | 120 张：万、筒、条与中发白，不用风牌、花牌 | 高 |
| 吃牌 | 只能吃上家；吃的优先级低于碰、杠 | 高 |
| 胡牌结构 | 一对将牌加四组顺子、坎或杠 | 高 |
| 查胡 | 一局结束后四家分别计算并两两结算 | 高 |
| 胡牌基础 | 胡牌者固定加 10 胡 | 高 |
| 普通对子 | 1 胡，不加幺 | 高 |
| 幺头对子 | 2 胡，不加幺 | 高 |
| 普通坎 | 2 胡 | 高 |
| 幺头坎 | 4 胡、1 幺 | 高 |
| 普通送杠 / 自杠 | 4 胡 / 6 胡 | 高 |
| 幺头送杠 / 自杠 | 8 胡 2 幺 / 12 胡 3 幺 | 高 |
| 放炮与自摸 | 不额外形成全局倍率；最后一张补成刻子时，点炮按碰、自摸按坎 | 高 / 实现解释 |
| 庄家倍率 | 只把庄家本人的胡数乘 2，幺数不翻 | 高 |
| 飘荤倍率 | 只把飘荤者本人的胡数乘 2；同一人兼庄时本人胡数乘 4 | 高 |
| 荤底 | 飘荤胡家另向其余三家各收 30 分 | 高 |
| 起手杠 | 起手四张相同可以立即杠胡，也可以继续打 | 高 |
| 包庄 | 四组单钓听顺、含吃单钓听顺、三组两对包香三类 | 中高 |

“对子”和“坎”是公开计分表中的独立项目，且查胡是四家分别结算。因此项目采用：没胡的人手里的对子和暗坎也参与查胡。公开页没有给出逐张拆分算法，但把它们全部忽略与公开计分表不相容。

## 3. 正确的本人倍率模型

庄家、飘荤都是某一位玩家自己的身份，不是整组两两关系的倍率。

```text
A 的本人倍率 = (A 是庄家 ? 2 : 1) × (A 飘荤 ? 2 : 1)
B 的本人倍率 = (B 是庄家 ? 2 : 1) × (B 飘荤 ? 2 : 1)

A 的折算胡 = A 的牌面胡 × A 的本人倍率
B 的折算胡 = B 的牌面胡 × B 的本人倍率

两两胡差 = A 的折算胡 - B 的折算胡
两两幺差 = A 的幺数 - B 的幺数
本房积分 = 两两胡差 + 两两幺差 × 10
```

例：飘荤闲家 17 胡对庄家 6 胡，应先算 `17×2=34` 和 `6×2=12`，胡差为 `22`。不能把原始差 `11` 同时乘上飘荤和庄家倍率。

这个模型允许身份倍率改变比较结果：庄家 6 胡对闲家 11 胡，折算后是 `12−11=+1`；因此结算协议必须同时保存 A、B 各自倍率和折算胡数，UI 也不能只展示原始胡差。

## 4. 三类包庄的实现口径

1. 四组碰、坎或杠后单钓，听口始终未换；点炮牌与手中单张能组成顺子：按飘荤包庄。
2. 四组中含吃后单钓，听口始终未换；点炮牌与手中单张能组成顺子：按普通胡包庄。
3. 三组碰、坎或杠加两对，未两对关门时，被关门前从未出现过的“香牌”点炮：按飘荤包庄；此前已经出现的是“臭牌”，不包。

包庄者代付另外两家原本应向胡家支付的正向份额；若有荤底，三家的荤底也全部由包庄者承担。代码必须记录：

- 单钓后是否换过听口；
- 关门前全桌已经出现过哪些弃牌；
- 两对关门是否仍有效。

A 级来源第二类包庄有疑似错字，因此项目按上下文理解为“已完成四组且其中含吃”的普通单钓听顺。该条属于中高置信实现，不应描述成毫无歧义的逐字原文。

## 5. 实现解释与本房房规

| 项目 | 当前决定 | 分类 | 原因 |
|---|---|---|---|
| 流局轮庄 | 只有庄家实际胡牌才连庄；闲家胡或流局都换到庄家的下一家 | 实现解释 | 公开页写“不是庄家胡牌则轮庄”，但没有单列流局 |
| 首局庄家 | 房主坐庄 | 本房房规 | 公开资料未说明如何选首庄 |
| 胡幺折分 | 1 胡 = 1 分、1 幺 = 10 分 | 本房房规 | 公开资料只说胡底、幺底分别对应底分，没有固定 10:1 |
| 坎上 | 用于锁牌、飘荤/关门/包庄组数与后续自杠；未坎上的真实暗坎仍计基础胡 | 实现解释 | 区分“查胡计值”和“对局中已锁定组型” |
| 未声明四张 | 按一坎加一张散牌，不追认自杠或两个对子 | 本房房规 | 公开资料未说明查胡时如何处理未报杠的四张 |
| 一炮多人 | 只取行牌顺序距出牌者最近的一家 | 本房房规 | 公开资料未给多人同时胡的裁决 |
| 补杠 / 抢杠胡 | 均不设；碰后第四张留在手里 | 本房房规 | 公开资料未明确，当前引擎也无对应动作 |
| 杠上开花 | 按普通自摸，不额外加番 | 本房房规 | 公开资料未给额外倍率 |
| 四家首张同牌 | 直接流局，并按正常流局换庄 | 本房房规 | 公开主要来源未列出 |
| 七对等扩展胡型 | 当前不支持 | 产品范围 | 公开主要来源只列四组一对、起手杠和飘荤 |
| 多种合法拆分 | 按当前房间积分配置取最终分值较高的合法拆分 | 本房房规 | 避免同一手牌因遍历顺序得到不同分数 |

## 6. 仍建议向邳州牌友确认的问题

在继续扩充房间配置前，优先找至少两位常打邳州麻将的朋友分别确认，避免相互暗示：

1. 牌墙摸完流局时，老家牌桌是下庄还是连庄？
2. 手里四张相同但没有报杠，最终查胡按自杠、坎加散张，还是另有算法？
3. “坎上”是否必须公开声明，未声明的暗坎是否仍查基础胡？
4. 幺底通常与胡底按什么比例结算，是否固定 10:1？
5. 一炮多人可胡时，是最近者优先、点炮者全包，还是允许一炮多胡？
6. 是否存在碰后补杠、抢杠胡、杠上开花额外分？
7. 开局四家首张同牌流局是否是当地常用规则，流局后庄位如何处理？

确认后不要只改文档：必须同时修改 `packages/rules`、`packages/server-core`（如涉及流程）、共享协议、规则弹窗、结算 UI 和测试，并执行 `npm run verify`。
